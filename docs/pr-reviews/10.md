**Reviewed**: 2026-09-22 · CI: green (npm run test) · Reviewer: Devin (PR Review playbook)

## Summary
- Scope: Updates tab badge and rows now share one data source — `useWebxdcUpdateStats` returns `{ stats, events }`, the 100-event `useWebxdcUpdateSearch` feed is deleted, and rows paginate client-side (200/"Show more").
- Risk: Medium — rewires the tab's data flow and changes search semantics; the refactor itself is clean and CI is green.
- Positives:
  - Single source of truth makes badge ≡ rows invariant by construction — nice simplification.
  - Dedup/`stats.has(identifier)` gating keeps `events` exactly consistent with `stats`.
  - Return-type refactor is complete (`stats.data?.stats` applied at all call sites); no other callers of the deleted hook.
- Concerns:
  1) **[major]** Under search, updates are filtered as `appMatches(q) AND updateMatches(q)` — payload hits from apps that don't match `q` silently disappear (ExplorePage.tsx:53).
  2) **[minor]** `stats.isLoading` is false while the stats query is still disabled (apps loading / apps error), so the tab briefly asserts "No webxdc updates found on your relays." (ExplorePage.tsx:215).
  3) **[minor]** `updateRows` doesn't reset on filter/data change; after expanding, a new search can render thousands of rows at once (ExplorePage.tsx:50).
  4) **[minor]** Client-side search misses `info`/`document`/`summary` values shown as badges (ExplorePage.tsx:106).
  5) **[nit]** `200` magic number duplicated; `parseWebxdcUpdate` re-parses every event per search.

## Decision
Comment (GitHub does not allow requesting changes on a PR authored by the same identity; submitted as a review comment with the concerns above).

## Next steps
1) Decide and document whether update search should be scoped to search-matching apps, or fetch stats for the unfiltered catalog.
2) Gate the skeleton/empty state on `apps.isLoading || stats.isLoading` (and `apps.isError`).
3) Reset `updateRows` when `searchQ`/`stats.data` changes.
4) Optionally include `info`/`document`/`summary` in the search haystack.
