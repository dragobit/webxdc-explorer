# PR Review Log #13

## Summary
- Scope: Implement `webxdc.sendToChat` / `importFiles` (user-mediated share dialog + file prompt) on top of the #12 sandboxed runner, per `docs/design/webxdc-sendToChat-importFiles.md`.
- Risk: Medium — new RPC surface crossing the sandbox → parent boundary, plus Blossom upload + kind 1 publish path.
- Positives:
  - Untrusted RPC args are validated before touching parent state (`parseSendOptions`, `parseImportFilter`).
  - User mediation is enforced correctly: the file picker is opened from a real click in the parent origin; pending requests are parked in refs and settled on unmount.
  - Bridge correctly targets the iframe.diy loader origin; identity push keeps `selfAddr`/`selfName` live after login.
  - Pure `xdcFile` helpers extracted with unit tests.
- Concerns:
  1) `base64` file variant has no size cap — unbounded decode in the parent (inline, major).
  2) `plainText.length` measured in UTF-16 units vs a byte limit (inline, minor).
  3) Picker-cancel leaves the import RPC parked until the user clicks Cancel (inline, minor).
  4) Upload success without a `url` silently drops the attachment (inline, minor).
  5) Post failure surfaces to the app as "sendToChat cancelled" (inline, minor).
  6) Image preview leaks object URLs (inline, nit).

## Decision
Request changes — the missing `base64` size bound undermines the stated 10 MiB guard on an untrusted input path.

## Next steps
1. Bound `file.base64` length in `parseSendOptions` (major).
2. Optionally: measure `plainText` in bytes, handle the file input `cancel` event, distinguish post-failure from user-cancel, revoke preview object URLs.
3. Publish path (Blossom + kind 1) still unverified end-to-end with a real login — noted in the PR's own E2E report.
