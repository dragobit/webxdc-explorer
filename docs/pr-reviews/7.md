# PR Review Log 7

## Summary
- Scope: Explore app icons (NIP-92 preview or icon extracted from the .xdc zip via a hand-rolled ZIP parser), kind-4932 update stats (count / participants / lastUpdate), and stat-based sort & filter (`updates>5` queries, "Only with updates", persisted sort).
- Risk: Medium — new network fetch path for arbitrary remote .xdc files plus a bespoke binary parser; the relay/UI changes are low risk.
- Positives:
  - `extractWebxdcIcon` is fail-soft (never throws), https-only enforced at the call site, ZIP64 rejected explicitly, and all offsets are bounds-checked.
  - Good test coverage for both the ZIP extractor (stored + deflated entries built in-test) and `parseStatsQuery`/`compareStat`.
  - Stats query is batched (50 `#i` per filter), deduped by event id, and zero-fills every requested identifier — clean contract for the UI.
  - Stat filters are correctly skipped while stats are still loading, avoiding a flash of wrongly-filtered results.
- Concerns:
  1) [major] Every card without a NIP-92 image eagerly downloads the full .xdc (up to 25MB) just for its icon — see inline on `src/lib/webxdcIcon.ts:50`.
  2) [minor] The Content-Length cap is bypassed when the header is absent (chunked/gzip responses) — `webxdcIcon.ts:53`.
  3) [minor] `limit: 1000` per stats chunk is shared across 50 identifiers and silently truncates — `useWebxdcUpdateStats.ts:36`.
  4) [minor] Stats queries (`updates>5`) only filter the first loaded page of apps — `ExplorePage.tsx:48`.
  5) [nit] "0 updates / 0" badges render on every inactive card — `AppCard.tsx:81`.
## Decision
Request changes — mainly for the eager full-`.xdc` downloads per card; everything else is follow-up quality.
## Next steps
1) Defer icon extraction to viewport-visible cards (or fetch via Range: EOCD tail → icon entry only).
2) Re-check `buf.byteLength` after `arrayBuffer()` when Content-Length is missing.
3) Hide the stats row when `count === 0`.
4) Optionally document/paginate the 1000-event stats cap and the loaded-page scope of stats queries.
